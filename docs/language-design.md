# Veyra 语言设计

## 定位

Veyra 是面向 JVM 的嵌入式静态业务脚本语言。它解决的问题不是“用另一门语言重写 Java”，而是让 Java 应用中的可变业务规则能够独立编写、提前检查、受控执行和热加载。

## 核心概念：宿主契约检查

Veyra 不自行定义业务领域模型。脚本中的 `Order`、`User` 等类型由 Java 宿主注册。编译器读取注册的 Java 类型元信息，检查：

- 属性是否存在，以及是否有允许的 getter/record accessor；
- 属性和参数的类型是否匹配；
- 查询和命令的名称、参数、返回值是否匹配；
- 当前脚本是否被授予访问这些能力的权限。

因此，Veyra 的静态检查边界由 Java 宿主提供，而不是由脚本自己重新声明一套领域实体。

## 纯计算与业务动作

Veyra 代码分为两类语义：

- 纯计算：变量、表达式、条件、纯函数和只读查询。
- 业务动作：通过 `emit` 产生类型化命令计划，不默认直接执行外部副作用。

Java 宿主负责事务、重试、幂等、审计和最终执行。这使脚本可以表达业务决策，同时避免把数据库、网络和线程模型偷偷塞进语言运行时。

## 明确不做的事情（MVP）

- 不定义复杂业务类、继承和泛型。
- 不开放任意 Java 方法、反射、文件、网络和线程访问。
- 不支持隐式类型转换或隐式真值判断。
- 不把 Veyra 设计成 Java、Kotlin 或 Python 的通用替代品。
- 不在语言层面解决事务和分布式一致性；这些责任属于宿主应用。
